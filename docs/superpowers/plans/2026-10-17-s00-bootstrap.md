# S00 — Bootstrap Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pnpm monorepo skeleton where every CLAUDE.md command exists, the Expo app runs on web and Android, and `pnpm verify` runs locally and in CI.

**Architecture:** The root holds the tooling: TypeScript base config, Biome, one Vitest config and the scripts. `packages/shared` is consumed as TypeScript source with no build step. `apps/server` is a Hono app run by tsx. `apps/mobile` is the create-expo-app SDK 58 default template, reset to one placeholder screen.

**Tech Stack:** Node 24.22.0, pnpm 12.14.0 (corepack), TypeScript ~6.0.3, Biome 2.5.15, Vitest ^5.0.5, Hono 4, Expo SDK 58 + Expo Router.

**Spec:** `docs/superpowers/specs/2026-10-17-s00-bootstrap.md`. Read it first; its Dependencies section is the approved list.

## Global Constraints

- Branch `s00-bootstrap`. No worktrees. Never push, merge or rebase. Conventional Commits, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `pnpm verify` is green before every commit.
- Dependencies: exactly the spec's list. No others without asking the owner (a stop). Add them by editing `package.json` and running `pnpm install`. `pnpm add` prompts for permission.
- TypeScript strict with `noUncheckedIndexedAccess`; ESM; no `any`; files kebab-case; named exports; comments explain why.
- Must run on Node 22 (≥22.13) and Node 24. `engines.node` is `">=22.13"`.
- Scripts must work on Arch and Ubuntu. No macOS-only commands or flags.
- Keep `apps/server/data/nationality-overrides.json`. Biome may reformat it, but no value changes.
- Out of scope (verbatim): **any data fetching, DB, real screens.**
- Acceptance criteria (verbatim):
  1. Clean `pnpm install` works; versions pinned as described.
  2. `pnpm verify` runs typecheck + Biome + Vitest for all packages and is green, with at least one real test in `shared` and `server`.
  3. `curl localhost:3001/health` returns `{"ok":true}` while `pnpm dev:server` runs.
  4. `pnpm dev:mobile` → web shows the placeholder including the value from `packages/shared` (proves Metro resolves the workspace package).
  5. Every command in `CLAUDE.md` exists; not-yet-implemented ones name their session.
  6. Editing a `.ts` file through Claude gets it formatted by the hook (show a before/after).
  7. `app.json` carries the app identity from VISION §11.
  8. After `/handoff` pushes, the PR's `verify (22)` and `verify (24)` checks pass (the handoff reports it).
- Owner steps (phone check, branch protection, `/usage`) are not tasks.

## Review Focus

1. `PORT` set but empty (`PORT=`), as a `.env` or shell often leaves it, should fall back to 3001, not crash or bind port 0. Pinned in Task 2.
2. A garbage `PORT` (`abc`, `3001abc`, `0`, `70000`) should fail at startup with a message naming `PORT`, not bind a random port. Pinned in Task 2.
3. `seasonLabel` at a century boundary (`2099` → `"2099-00"`) and at a decade (`2009` → `"2009-10"`). Pinned in Task 1.
4. `pnpm test <filter>` should run only the matching tests. A filter that silently runs everything (or nothing) breaks the CLAUDE.md workflow. Verification step in Task 2.
5. The Node 22 leg should not first fail in CI. Run `pnpm verify` under Node 22 locally. Verification step in Task 4.
