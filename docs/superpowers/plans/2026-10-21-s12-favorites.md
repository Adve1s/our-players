# S12 — Search, favorites, hidden Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a Search tab that stars or hides any player of the selected leagues, Favorites and Hidden lists with undo in Settings, and Today following those preferences.

**Architecture:** pure preference actions in `apps/mobile/src/state/prefs.ts` (red/green), pure list/search helpers in `src/lib/players.ts`, two TanStack Query hooks over the existing typed client, a shared `PlayerItem` row and `SearchField`, then the screens and `pnpm screenshots`. No server or contract change.

**Tech Stack:** Expo Router 58, React Native + react-native-web 0.21, TanStack Query 5, Zustand persist, Vitest, Playwright (screenshots).

**Spec:** `docs/superpowers/specs/2026-10-21-s12-favorites.md` (read it first; it holds the copy text and layouts).

## Global Constraints

Acceptance criteria (verbatim, SESSIONS.md §S12):
1. Pure tests for preference actions: favoriting unhides; hiding unfavorites; toggles are idempotent; `version` preserved.
2. On a device: search "porzingis" → star → he appears on Main for a day he played, even with no countries followed.
3. Hiding a Latvian removes him from Main; unhiding brings him back.
4. Screenshots reviewed: results, empty search, both lists.
5. `pnpm verify` green.

Out of scope (§S12 lists none; carried): player page and its actions, pressable rows/cards (S13); anything team-based (v2); offline persistence (v2).

Project rules that bind every task:
- Preferences change only through the pure functions in `src/state/prefs.ts`; the persisted object keeps `version: 1`.
- A deselected league is gone everywhere: Search sends only the selected leagues; Settings lists show only selected leagues' players.
- Server data only via TanStack Query hooks in `src/api/queries.ts`, keys include what they depend on; components never call `fetch`.
- Style only via `useTheme()` tokens; no hard-coded colors or font sizes. State in `aria-*` props (`aria-checked`), not `accessibilityState`. Every touchable has an `accessibilityLabel`; targets ≥ 48 px (`t.space.xl * 2`).
- Every screen handles loading, empty, error and offline (`fetchStatus === 'paused'`) states.
- No new dependency. Framework APIs checked with context7 (`useFocusEffect` from `expo-router` already confirmed: cleanup runs on blur).
- `pnpm verify` green before every commit except the Task 2 red commit. Conventional Commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A query longer than 50 characters — the server's `searchQuerySchema` rejects it (400); `searchTerm` caps it at 50 (pinned in Task 2).
2. A favorite whose ID the server no longer returns — no row, not counted in the card's `aside` (pinned in Task 2 `listRows`).
3. A favorite of a deselected league — absent from the list but still stored, back when the league is (pinned in Task 2 `listRows`; stored lists untouched).
4. Remove, then leave Settings and come back — the removal is final, no Undo row (checked in Task 6's `settings-undo` flow by tab switching).
5. Fast typing — results for an older term never replace a newer one (query keyed by the debounced term; checked by the screenshot waits, which match the final term's text).
