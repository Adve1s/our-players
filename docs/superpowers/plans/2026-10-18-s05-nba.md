# S05 — ESPN NBA adapter + jobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** NBA data flows from ESPN through the same jobs and scheduler as the NHL, and `pnpm recap` shows both leagues.

**Architecture:** `apps/server/src/sources/espn-nba/` mirrors `sources/nhl/`: raw zod schemas and pure mappers, specified first by the test-writer from the fixtures, then implemented. Thin fetchers come after them. `src/jobs/adapters.ts` gives each league one adapter object, and every job dispatches through `ADAPTERS[args.league]`. The scheduler keys "last run" by job and league, read from `job_runs.args->>'league'`.

**Tech Stack:** TypeScript (strict, ESM), zod 4, Drizzle + PGlite, Vitest, Biome.

**Spec:** `docs/superpowers/specs/2026-10-18-s05-nba.md` (design). Contract: `docs/SESSIONS.md` §S05. Sources: `docs/sources/espn-nba.md`.

## Global Constraints

Copied from §S05:

**Out of scope:** API, app.

**Acceptance criteria**
1. Mapper tests for every NBA fixture with hand-read values: regular line, DNP with reason, OT game, preseason, statuses, period scores, shooting splits.
2. A test that reorders the label and stat arrays gets identical output.
3. Country mapping: "Latvia" → LVA, "Cameroon" → CMR, "USA" → USA; aliases for every spelling seen in fixtures; an unknown name → `null` + warning (tested).
4. Overrides reach NBA players: a test over the Embiid and Towns athlete fixtures yields USA and DOM with source `override`; live, after the roster job, the database shows the same (show the query).
5. NBA ingestion keeps the idempotency and stub/enrichment guarantees (tests).
6. Live, run by you: backfill a date Porziņģis played; `pnpm recap` shows NHL and NBA Latvians.
7. The season-stats job stays within the documented request budget (logged count).
8. The scheduler runs both leagues: a daily job that ran today for NHL is still due for NBA, and an NBA results run (day loop and corrections) fetches only ESPN URLs (tests).
9. `pnpm verify` green.

Owner ruling: `espn-nba/overview/3102531.json` is exempt from AC1 (no mapper reads it).

Project rules:
- No new dependencies. No migration.
- Fixtures come only from `pnpm fixtures:record`; never edit one. Tests may mutate a freshly loaded copy (`loadFixture` parses fresh each call).
- Errors name the source and endpoint: `espn-nba <endpoint>: …`, where `<endpoint>` is the fixture directory name (`scoreboard`, `summary`, `teams`, `roster`, `athlete`, `byathlete`).
- Mappers are pure and synchronous. Stats are mapped by label, never by array position. Country names go through `packages/shared/src/countries.ts` only.
- `pnpm verify` is green before every commit, except Task 2's red commit, where the only failures may be the new tests failing on "not implemented".
- Owner steps (AC4 live, AC6) are not tasks. They come after the final review.

## Review Focus

1. A SCHEDULED scoreboard game: ESPN sends `score` `"0"` and may omit `linescores`. Expect `homeScore`/`awayScore` `null` and `periodScores` `null`. Test in Task 2.
2. A roster or athlete with no `birthPlace`, or with `birthPlace` lacking `country`. Expect `birthCountry` `null` and **no** warning (absent is not unknown). Test in Task 2.
3. An athlete with no `team` (free agent, retired). Expect `currentTeamExternalId` `null`. Test in Task 2.
4. A box-score `displayName` without a space ("Nene"). Expect `firstName` `''`, `lastName` `'Nene'` (the NHL stub convention). Test in Task 2.
5. The same athlete on two byathlete pages (rows shift between requests). Count him once and don't call that truncation. Test in Task 4.
