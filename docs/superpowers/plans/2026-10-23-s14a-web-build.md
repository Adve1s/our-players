# S14a — Web build as a home-screen app (local) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the Expo web export is a finished home-screen app (manifest, icons, iOS tags, help page), built by one command, served locally as production, with a Cloudflare deploy workflow written but off.

**Architecture:** `expo export -p web` (SPA, `web.output: "single"`) copies `apps/mobile/public/` into `dist/`; the screenshot script's static server becomes a shared module behind `pnpm serve:web`; Cloudflare Workers static assets (`wrangler.jsonc`, `not_found_handling: "single-page-application"`) host it from S14b on, deployed by a hand-triggered workflow.

**Tech Stack:** Expo 58 / Expo Router, react-native-web, Playwright (dev, already installed), Node `http`, Vitest, GitHub Actions, wrangler via `pnpm dlx` (CI only).

**Spec:** `docs/superpowers/specs/2026-10-23-s14a-web-build.md`

## Global Constraints

- **Out of scope:** going online (S14b); production `CORS_ORIGINS` (S10b).
- **Acceptance criteria**
  1. The static build is produced by one command and screenshot-checked.
  2. Served locally as a production build: deep links work on reload; the manifest and icons load (show them).
  3. Hosting choice recorded; the deploy config is ready for S14b and doesn't run on a push to `main`.
  4. `pnpm verify` green.
- No new dependency in any `package.json` (wrangler runs only through `pnpm dlx wrangler@4.151.3` in CI and for the dry run).
- Scripts run on Arch and Ubuntu, Node 22 and 24; no macOS-only commands.
- App code: theme tokens only (`useTheme()`), `aria-*` for state, English text, route files `export default`, everything else named exports, files kebab-case.
- Every commit: `pnpm verify` green; Conventional Commits ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Screenshots: `PLAYWRIGHT_CHROMIUM_PATH=/usr/bin/chromium pnpm screenshots`; look at the new images before calling a UI task done.

## Review Focus

1. A request with malformed percent-encoding (`/%E0%A4%A`) to `serve:web` → answered (index.html, 200), the server keeps running. Test in Task 1.
2. A traversal path (`/..%2fpackage.json`) → index.html, never a file outside the export. Test in Task 1.
3. A manifest icon missing from `dist/` → the SPA fallback answers it with index.html and 200, so the check must look at `content-type: image/png`, not only the status. Check in Task 3.
4. A deploy with `WEB_API_URL` empty or `http://…` → the workflow fails before building (an `http` API from an `https` site is blocked as mixed content). Checked in Task 4.
5. A deep link with a query (`/settings?x=1`) reloads to the app. Test in Task 1.

- [ ] **Step 2: Write `.github/workflows/deploy-web.yml`** exactly:

```yaml
name: Deploy web

# Only by hand until S14b adds `push: branches: [main]` (D-056).
on:
  workflow_dispatch:

permissions:
  contents: read

concurrency: deploy-web

jobs:
  deploy:
    runs-on: ubuntu-latest
    env:
      EXPO_PUBLIC_API_URL: ${{ vars.WEB_API_URL }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-node@v7
        with:
          node-version-file: .tool-versions
      - run: corepack enable
      - name: Check WEB_API_URL
        # Unset, the site would call http://localhost:3001; http:// is blocked from an https page.
        run: |
          case "$EXPO_PUBLIC_API_URL" in
            https://*) ;;
            *) echo "::error::Set the WEB_API_URL repository variable to the API's https:// URL"; exit 1 ;;
          esac
      - run: pnpm install --frozen-lockfile
      - run: pnpm build:web
      # wrangler-action would `pnpm add` wrangler inside the workspace; dlx keeps it out of package.json.
      - run: pnpm dlx wrangler@4.151.3 deploy
        working-directory: apps/mobile
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
```
