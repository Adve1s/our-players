# S09 — Main page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Today tab becomes the morning recap: game-day stepper, game cards with the shown players' rows (lines, DNP, not in lineup, and the new `upcoming` rows), collapsed Other games, loading/empty/error/offline states, pull to refresh. The server and `pnpm recap` gain `upcoming` rows.

**Architecture:** `gameDayRows` (D-038) gets a fourth row kind; the contract and the recap follow. Card text moves to one pure shared module (`packages/shared/src/format.ts`) used by the recap and the app; app-only formatting (local time, day label, row text, screen-reader labels, which message a day shows) lives in pure `apps/mobile/src/lib/` modules. The screen reads `/v1/meta` and `/v1/days` through TanStack Query, with the day in the `date` search param.

**Tech Stack:** Expo SDK 58 / Expo Router 58 (`useLocalSearchParams`, `router.setParams`), React Native 0.88 + react-native-web 0.21, TanStack Query v5 (`focusManager`), Zustand, zod 4, Hono, Drizzle + PGlite, Playwright, Vitest. Check Expo Router and TanStack Query APIs with context7 before writing code against them.

**Spec:** `docs/superpowers/specs/2026-10-20-s09-main-page.md` (approved 2026-10-20). Read it first: it fixes every text format, the state priority, the component list and the screenshot table; this plan doesn't repeat them.

## Global Constraints

From SESSIONS.md §S09, verbatim:

**Out of scope:** navigation targets (player/game pages arrive in S13); anything team-based (v2).

**Acceptance criteria**
1. Formatting helpers unit-tested (e.g. `.933`, `18:32`, `Final/OT`, start time in an injected timezone).
2. Screenshots reviewed and fixed by Claude for: a busy night; a night with a goalie, a skater and an NBA player; DNP rows; an upcoming day with `upcoming` rows; an empty day; the error state; dark mode.
3. With default preferences, opening the app shows the latest game day (seeded or real data).
4. API tests for `upcoming` rows: a followed player whose current team plays a scheduled game gets one and the game sorts first; a live game and a final game without a stored box score give one too (`pnpm recap` prints the final one as "Waiting for stats"); a favorite from another country gets one; a hidden player, a player with no current team and a player with a line in another game that day don't; a final game keeps its line, DNP and "Not in lineup" rows; `pnpm recap` prints upcoming rows.
5. Works on web and Android.
6. `pnpm verify` green.

Also:
- Also out of scope (spec): keeping server data on the device across restarts (v2 revisit list), prefetching the next game day, a web refresh button, tapping cards (S13), favorite/hide actions (S12).
- Owner decisions: upcoming text `Not started` / `In progress` / `Waiting for stats`, identical in the app and `pnpm recap`; query cache in memory only.
- No new dependencies. One new fixture, recorded only with `pnpm fixtures:record nhl boxscore 2025021067` (Task 5). Never edit a fixture; in-memory variants inside test helpers are fine (precedent: `api-seed.ts` `score()`).
- D-049 changes exactly two existing tests: `game-day-rows.test.ts` "no not-in-lineup row when the game isn't FINAL" and "no not-in-lineup row for a FINAL game whose box score isn't stored" (both now expect one `upcoming` row). No other existing test's expectation changes; `seedApiDb()` itself is not changed.
- `apps/mobile` never imports `apps/server`. Mobile rules (`.claude/rules/mobile.md`): server data only through Query hooks whose keys include the prefs lists; theme tokens only (no colour or font-size literals); `accessibilityLabel` on every touchable; state in `aria-*` props (`aria-disabled`, `aria-expanded`), not `accessibilityState`; text respects font scale.
- Mobile tests in `apps/mobile/test/*.test.ts` import only pure modules (no `react-native`).
- `pnpm verify` green before every commit except Task 2's red-phase `test:` commit.
- Owner steps are not plan tasks: after the final review the controller walks the owner through Android in Expo Go (AC5) and points at the "You:" line (a few real mornings) for the briefing's Next.

## Review Focus

1. A bad `date` param (`?date=foo`, `?date=2026-02-30`, a repeated `?date=a&date=b`) → the app shows the latest day, never a 400 error screen. Pinned in Task 2 (`dateParam` cases).
2. Every selected league has `latestGameDate: null` (empty DB, before a season) → "No games yet.", not an endless skeleton. Pinned in Task 2 (`latestDate` → `null`) and Task 4 (screen branch).
3. Card values at the edges: TOI `0:05` and `65:00`, `+/-` of `0` and `-1`, save % `1` → `1.000` and `null` (left out), no decision (left out). Pinned in Task 2 (shared format table).
4. DNP reasons in other casings or none (`"COACH'S DECISION"`, `"INJURY/ILLNESS"`, `null`) → sentence case or plain `DNP`. Pinned in Task 2 (`rowText` table).
5. A day after the latest game day with no next game day (`nextGameDate: null`) → the message without a button; "after" compares league schedule dates, never the device's clock. Pinned in Task 2 (`dayMessage` cases).
