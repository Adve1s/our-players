# S01 — Data spike + fixtures Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tested polite HTTP client, a fixture recorder, a committed fixture set for NHL and ESPN NBA, a throwaway `pnpm spike`, and `docs/sources/{nhl,espn-nba}.md` answering VISION §9.

**Architecture:** `apps/server/src/http/polite-client.ts` is the only code that calls upstream. Two `tsx` scripts in `apps/server/scripts/` use it: the recorder (`fixtures-record.ts` + `endpoints.ts`) and the spike (`spike/`). Fixtures land in `apps/server/test/fixtures/<source>/<endpoint>/`.

**Tech Stack:** Node 22/24, TypeScript strict, Vitest 5 (fake timers), tsx, Biome. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-17-s01-data-spike.md` (read it — it holds the endpoint table, the fixture candidates and the §9 answer plan).

## Global Constraints

- **Out of scope:** DB, normalized model, adapters, anything in `apps/mobile`.
- **Acceptance criteria**
  1. Polite-client tests cover spacing, retry with backoff on 429/503, `Retry-After`, timeout, no retry on 404, User-Agent header.
  2. `pnpm spike --date <date>` prints at least one NHL and one NBA Latvian line, plus request count and runtime.
  3. Fixture set recorded with `.meta.json` files and committed.
  4. Both source docs answer all eight questions with evidence (endpoint, field path, example value).
  5. `pnpm verify` green.
- **Request budget:** ≤ 250 live upstream requests for the whole session. Every live request goes through the polite client (≤ 1 request/s per host). Each live-calling task's report states the polite client's `requestCount` for that task; the controller keeps a running total in the ledger. A task that would exceed its own allowance stops and reports instead.
- Tests never touch the network. Fixtures are never hand-edited (re-record with `--force` or `--as`).
- No new dependencies. No `any` (use `unknown`; the throwaway spike may narrow with local type assertions).
- User-Agent: `OurPlayers/<version> (+<contactUrl>)`, version from `apps/server/package.json`, contactUrl default `https://github.com/Adve1s/our-players`.
- Nationality: record evidence and a *proposed* wording only; do not edit VISION.md, CLAUDE.md or DECISIONS.md.
- Small Conventional Commits; `pnpm verify` green before each commit. Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Retry-After as an HTTP date in the past or garbage** → treated as no header (use computed backoff), never a negative or NaN sleep. Test in Task 1.
2. **Concurrent `get` calls to one host** (e.g. `Promise.all`) → still spaced ≥ 1 s apart, not bursted. Test in Task 1.
3. **A non-JSON or non-2xx response while recording** → nothing written, exit 1 naming the URL and status. Test in Task 2.
4. **Recording into a missing endpoint directory** → directories created. Test in Task 2.
5. **Unknown source/endpoint on the recorder CLI** → exit 1 listing valid endpoints, no request made. Test in Task 2.

### Task 1: Polite client (red/green)

**Files:**
- Create: `apps/server/src/http/polite-client.ts`
- Modify: `apps/server/src/config.ts`, `apps/server/package.json` (add `"version": "0.1.0"`)
- Test: `apps/server/test/polite-client.test.ts`, `apps/server/test/config.test.ts`

**Interfaces:**
- Produces:
  ```ts
  export type PoliteClientOptions = { userAgent: string; fetch?: typeof globalThis.fetch; minIntervalMs?: number /*1000*/; timeoutMs?: number /*15000*/; maxRetries?: number /*3*/; baseDelayMs?: number /*1000*/; maxRetryAfterMs?: number /*60000*/; random?: () => number /*Math.random*/ };
  export type PoliteResponse = { url: string; status: number; text: string; bytes: number }; // bytes = UTF-8 byte length of text
  export class HttpError extends Error { constructor(readonly url: string, readonly status: number | null, message: string) } // status null = network/timeout
  export type PoliteClient = { get(url: string): Promise<PoliteResponse>; readonly requestCount: number; readonly requestsByHost: ReadonlyMap<string, number> };
  export function createPoliteClient(o: PoliteClientOptions): PoliteClient;
  export function userAgent(version: string, contactUrl: string): string;
  // config.ts
  export function loadConfig(env): { port: number; contactUrl: string } // CONTACT_URL, default https://github.com/Adve1s/our-players
  ```
- Backoff before retry n (0-based): `baseDelayMs * 2 ** n + random() * baseDelayMs`; a valid `Retry-After` (delta-seconds or HTTP date, in the future) replaces it; one > `maxRetryAfterMs` throws `HttpError` immediately. Retry on 429, 5xx, network error, timeout (AbortController + setTimeout). Other non-2xx → `HttpError` without retry. Spacing is per `new URL(url).hostname`, applies to every attempt including retries, and serializes concurrent calls.

- [ ] **Step 1: Write the failing tests** — `vi.useFakeTimers()`, fake `fetch = vi.fn()` returning `new Response(body, { status, headers })`, `random: () => 0`. Record `Date.now()` per fetch call. Tests:
  - `spaces two requests to the same host by ≥ 1000 ms` (also via `Promise.all` — Review Focus 2) and `does not delay requests to different hosts`.
  - `retries 429 with exponential backoff` (3× 429 then 200 → 4 calls; gaps ≥ 1000, 2000, 4000 ms) and `retries 503`.
  - `gives up after maxRetries and throws HttpError with the last status`.
  - `honors Retry-After seconds` (`Retry-After: 5` → next call ≥ 5000 ms later) and `honors Retry-After as an HTTP date`; `ignores a past or unparsable Retry-After` (Review Focus 1); `throws without waiting when Retry-After exceeds 60 s`.
  - `aborts a request after timeoutMs and retries` (fake fetch that resolves only on abort signal → rejects; second call 200).
  - `does not retry 404` (1 call, `HttpError` status 404).
  - `sends the User-Agent header` (`OurPlayers/0.1.0 (+https://github.com/Adve1s/our-players)`, built with `userAgent()`).
  - `counts every attempt in requestCount and requestsByHost`.
  - config: `defaults contactUrl` / `reads CONTACT_URL`; update existing `toEqual({ port })` expectations to include `contactUrl` (same assertions, extended shape).
