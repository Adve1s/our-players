# S14b — Web go-live Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** the web app goes online at `https://ourplayers.adveis.dev`, deployed by CI on every relevant push to `main`, with the "Add to Home Screen" help page reachable from Settings.

**Architecture:** S14a's assets-only Worker (`apps/mobile/wrangler.jsonc`) gains a Workers Custom Domain and drops `workers.dev`; `deploy-web.yml` gains its push trigger. The only app change is a web-only link in Settings → About. No server change: production `CORS_ORIGINS` is already `https://ourplayers.adveis.dev`.

**Tech Stack:** Expo Router (web), Cloudflare Workers static assets via `pnpm dlx wrangler@4.151.3`, GitHub Actions, Playwright screenshots.

**Spec:** `docs/superpowers/specs/2026-10-26-s14b-web-live.md`

## Global Constraints

From §S14b, verbatim:

**Out of scope:** new features.

**Acceptance criteria**
1. Deployed URL works on desktop and iPhone Safari; added to the home screen it opens standalone with the right icon (you, or your iPhone friend).
2. Deep links work on reload on the host.
3. Production API accepts the web origin and rejects others.
4. `pnpm verify` green.

Also:
- The web origin is exactly `https://ourplayers.adveis.dev`; the API is `https://api.ourplayers.adveis.dev`.
- Wrangler stays pinned at `4.151.3` and runs through `pnpm dlx` (nothing added to `package.json`).
- On this laptop run `pnpm verify` as `pnpm typecheck && pnpm lint && pnpm test --maxWorkers=2` (PROGRESS Known issues).
- Owner steps (token, secrets, `wrangler login`, the first deploy, phone tests) are not plan tasks; they follow the final review.

## Review Focus

1. The help link on Android: it must not render (`Platform.OS !== 'web'`); the Android app is already installed. Checked by reading the diff (no Android screenshot tooling).
2. A push to `main` touching only `apps/server/**` or `docs/**` must not deploy the web app — the `paths` list.
3. A hand-started run on a non-`main` branch still skips (`if: github.ref == 'refs/heads/main'` kept).
4. `workers_dev: false` + a custom-domain route must pass `wrangler deploy --dry-run` (config schema).
5. Keyboard and screen-reader use of the link on web: it is a `Pressable` with `accessibilityRole="link"` and an `accessibilityLabel`, reachable by Tab.

```ts
{
  name: 'settings-install-link',
```

- [ ] **Step 4: DEPLOY.md §10 "Web app" and D-061**

`docs/DEPLOY.md`: retitle to cover both (`# Deploying the backend and the web app`) and add to the intro that the web app is at `https://ourplayers.adveis.dev` (§10). New `## 10. Web app` with, in the doc's existing style (**On your computer** blocks, "Success:" lines):
- What runs where: Cloudflare Workers static assets, Worker `our-players`, custom domain `ourplayers.adveis.dev` (DNS record and certificate created by Cloudflare on the first deploy); built from `apps/mobile` with the API URL baked in (`WEB_API_URL` repo variable = `https://api.ourplayers.adveis.dev`).
- First-time setup: (1) API token: Cloudflare → My Profile → API Tokens → Create Token → template "Edit Cloudflare Workers"; Account Resources: your account; Zone Resources: Specific zone → `adveis.dev`; create and copy it once. (2) `gh secret set CLOUDFLARE_API_TOKEN`, `gh secret set CLOUDFLARE_ACCOUNT_ID` (account ID from the dashboard's account home → "Copy account ID"), `gh variable set WEB_API_URL --body https://api.ourplayers.adveis.dev`. (3) The first deploy may run from a laptop: `pnpm dlx wrangler@4.151.3 login`, then `EXPO_PUBLIC_API_URL=https://api.ourplayers.adveis.dev pnpm build:web` and `pnpm dlx wrangler@4.151.3 deploy` in `apps/mobile`; `wrangler logout` afterwards.
- Deploy: automatic on a push to `main` that touches `apps/mobile/**`, `packages/shared/**`, `pnpm-lock.yaml` or the workflow; by hand: GitHub → Actions → Deploy web → Run workflow (branch `main`). `gh run list --workflow deploy-web.yml` shows runs.
- Rollback: Cloudflare dashboard → Workers & Pages → `our-players` → Deployments → pick the previous one → Rollback; or `pnpm dlx wrangler@4.151.3 rollback` in `apps/mobile` (logged in). A rollback lasts until the next push deploys.
- Checks (**On your computer**): `curl -sS -o /dev/null -w '%{http_code} %{content_type}\n' https://ourplayers.adveis.dev/player/nhl-8478402` → `200 text/html…` (deep link); `curl -sS -o /dev/null -w '%{http_code} %{content_type}\n' https://ourplayers.adveis.dev/manifest.json` → `200 application/json`; the two CORS curls from the design doc ("CORS check") with their expected results.
- If the token stops working, §6 "Cloudflare" covers rolling it. Also update §1's `CORS_ORIGINS` row note "the web build's address (S14b)" → "the web app's address (§10)".

`docs/DECISIONS.md`: append **D-061 — Web app only on `ourplayers.adveis.dev`, no `workers.dev`; first deploy from the laptop** (2026-10-27, accepted): the custom domain is set in `wrangler.jsonc` (Cloudflare manages its DNS record and certificate), `workers_dev: false` because the API allows only that origin; the workflow deploys on pushes to `main` touching the paths above; the first deploy ran from the owner's laptop via `wrangler login` because the workflow deploys only `main` and the phone test was in-session; the first CI run after the merge checks the token. Alternatives: also serving `workers.dev` (a second `CORS_ORIGINS` entry for a copy nobody needs), a DNS record made by hand (a custom domain makes it), first deploy after the merge (no phone test in session). Supersedes the `workers.dev` default in D-056. Match the existing entries' one-paragraph format.
