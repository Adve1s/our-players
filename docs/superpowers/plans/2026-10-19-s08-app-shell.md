# S08 — App shell, settings, screenshot tooling Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app gets tabs (Today, Search, Settings), light/dark theme tokens, a persisted preferences store, a working Settings screen against `/v1/countries`, friendly error/offline states, an error boundary, and `pnpm screenshots`.

**Architecture:** Pure logic (`src/state/prefs.ts`, `src/lib/countries.ts`, `src/lib/errors.ts`, shared `countryName`) is red/green-tested with Vitest. A Zustand `persist` store wraps the pure updates; TanStack Query reads `/v1/countries` through S07's `createApiClient`. The web build is a single-page export. `pnpm screenshots` boots a fixture-seeded API (server-owned script), exports and serves the web build, and drives Playwright Chromium.

**Tech Stack:** Expo SDK 58 / Expo Router 58.0.23 (`Tabs`, `ErrorBoundary`, `ThemeProvider`/`DarkTheme`/`DefaultTheme` re-exported from `expo-router`), React Native 0.88 + react-native-web, TanStack Query v5, Zustand v5 (`persist`, `createJSONStorage`), AsyncStorage 2.2.0 (SDK-pinned), zod 4, Playwright (library), tsx, Vitest. Check Expo Router, TanStack Query and Zustand APIs with context7 before writing code against them.

**Spec:** `docs/superpowers/specs/2026-10-19-s08-app-shell.md` (approved 2026-10-19). Read it first: it fixes the copy, the token names, the store shape, the Settings layout and the screenshot list; this plan doesn't repeat them.

## Global Constraints

From SESSIONS.md §S08, verbatim:

**Out of scope:** Main page content (S09), search and favorites (S12), player and game pages (S13).

**Acceptance criteria**
1. A fresh install defaults to Latvia + both leagues; preferences survive a web reload and an Android relaunch.
2. Preferences store logic is unit-tested (pure reducer-style functions).
3. `pnpm screenshots` produces PNGs; Claude looks at them and fixes visible layout problems (show before/after in the session).
4. Runs on Android (Expo Go, talking to the dev API over the LAN) and web without errors; API down → friendly error.
5. `pnpm verify` green.

Also:
- Also out of scope (spec): Favorites/Hidden lists in Settings, the privacy-policy link, offline caching of server data, tab icons, NetInfo.
- Owner decision: every country can be unticked; at least one league stays on.
- New dependencies, all in `apps/mobile`, exactly these: `@tanstack/react-query`, `zustand`, `@react-native-async-storage/async-storage@2.2.0` (SDK 58's pinned version, from `node_modules/expo/bundledNativeModules.json`), dev `playwright`, dev `tsx` (same range as `apps/server`). Also `zod` (same range as `packages/shared`, already in the workspace) for `restorePrefs`. Nothing else. pnpm's `minimumReleaseAge` applies: if the newest version is refused, take the newest accepted one.
- `apps/mobile` never imports `apps/server` (CLAUDE.md rule 10). The screenshot API script lives in `apps/server/scripts/` and is started as a child process.
- Mobile rules (`.claude/rules/mobile.md`): routes in `src/app/` with `export default`; components `src/components/`, API hooks `src/api/`, prefs `src/state/`, pure helpers `src/lib/`; server data only through TanStack Query hooks; prefs change only through the pure update functions; style only through theme tokens (no color or font-size literals in components); every touchable has an `accessibilityLabel`; text respects font scale (never `allowFontScaling={false}`); no logos/photos.
- Mobile tests live in `apps/mobile/test/*.test.ts` (already matched by `vitest.config.ts`); they import only pure modules (no `react-native`, no AsyncStorage).
- `pnpm verify` green before every commit except Task 2's red-phase `test:` commit.
- Owner steps are not plan tasks: after the final review the controller walks the owner through Android in Expo Go over the LAN (AC1 relaunch, AC4) and the Play Console reminder.

## Review Focus

1. Stored prefs from an older or hand-edited build (unknown league `"KHL"`, empty `leagues`, a code like `"XX"`, a non-object) → the defaults, never a crash or a 400 later. Pinned in Task 2 (`restorePrefs` cases).
2. A selected country that has no active players any more (missing from `/v1/countries`) → still listed so it can be unticked. Pinned in Task 2 (`countryRows`).
3. Country search with accents/case/whitespace (`"  LAT "`, `"cote"` for "Côte d'Ivoire") → matches. Pinned in Task 2.
4. API unreachable on first launch → Settings shows the friendly message and Try again; leagues still toggle. Pinned in Task 6 (`settings-api-down` shot) and Task 7 (looked at).
5. `EXPO_PUBLIC_API_URL` with a trailing slash (`http://192.168.1.5:3001/`) → no `//v1`. Pinned in Task 2 (`apiBaseUrl` case).
