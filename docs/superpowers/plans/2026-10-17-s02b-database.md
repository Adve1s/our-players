# S02b — Database schema and repositories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Postgres schema per VISION §8 in Drizzle, dev/test/prod DB clients, `db:*` scripts, and repositories that store S02a's normalized model idempotently, plus nationality recomputation with override warnings, with the repositories and the recomputation written test-first.

**Architecture:** `apps/server/src/db/` holds the schema, the clients (PGlite on disk, PGlite in memory, node-postgres) behind one `Db` type, a CLI for migrate/reset, and one small module per repository. Every upsert is a single `insert … on conflict … do update … where (cols) is distinct from (excluded cols)`, so a repeat write is a no-op. `apps/server/src/nationality/recompute.ts` applies `resolveNationality` to stored players and reports override warnings.

**Tech Stack:** TypeScript strict, Drizzle ORM 0.45.4 + drizzle-kit 0.31.11, PGlite 0.5.10, node-postgres 8.23.1, zod 4, Vitest 5, Biome.

**Spec:** `docs/superpowers/specs/2026-10-17-s02b-database.md` — it holds the table list, client matrix, natural keys, error and warning wording, and test list; this plan doesn't repeat them. Read it before each task.

## Global Constraints

- **Out of scope:** adapters, jobs, API, app.
- **Acceptance criteria**
  1. `pnpm db:migrate` succeeds on a fresh local DB, and `pnpm db:generate` right afterwards produces no new migration.
  2. Writing the same normalized game and lines twice leaves identical rows (PGlite test).
  3. Invalid stat payloads are rejected on write with a clear error.
  4. Nationality recomputation (PGlite tests): stored players get their nationality and its source from the resolver; an override whose player isn't in the DB, or whose name doesn't match the stored name, logs a warning.
  5. `pnpm verify` green.
- New dependencies, approved, exact versions, all on `apps/server`: `drizzle-orm` 0.45.4, `@electric-sql/pglite` 0.5.10, `pg` 8.23.1 (runtime); `drizzle-kit` 0.31.11, `@types/pg` 8.23.1 (dev). Nothing else.
- Migrations in `apps/server/drizzle/` are generated by `drizzle-kit generate` and never hand-edited. Leagues are seeded in code, not in a migration.
- `packages/shared` and `apps/mobile` are not edited. The overrides file and fixtures are never edited.
- No `any`; `unknown` + zod. Named exports; kebab-case files; DB names snake_case; comments explain why.
- Tests never touch the network; DB tests use `createTestDb()` (in-memory PGlite).
- Red/green: Task 2's tests are not changed afterwards. If one looks wrong, stop and report it (owner decides).
- Small Conventional Commits; `pnpm verify` green before each commit, except Task 2's red-phase `test:` commit (only the new tests may fail, only on "not implemented"). Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **The same natural key twice in one batch** (a traded player on two rosters in one fetch, a duplicated box-score row) → Postgres refuses `on conflict do update` touching a row twice. Expected: the last occurrence wins, no error. Tests in Task 2 (players, stat lines).
2. **Empty batch** → returns 0 and writes nothing (Drizzle throws on `values([])`); `upsertStatLines(db, game, [])` deletes the game's lines. Tests in Task 2.
3. **A player with `currentTeamExternalId: null`** (free agent) → stored with `current_team_id` null, no "unknown team" error. Test in Task 2.
4. **A DNP line** (`played: false`, `stats: null`, `dnpReason` set) → stored with `stats` null and the reason. Test in Task 2.
5. **An override equal to the birth country** → source `override` (D-030), and a recompute after the override is removed flips the source to `birth` even though the nationality is unchanged. Test in Task 2.
