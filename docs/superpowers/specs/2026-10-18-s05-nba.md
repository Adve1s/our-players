# S05 — ESPN NBA adapter + jobs: design

Session S05, branch `s05-nba`. Spec: `docs/SESSIONS.md` §S05. ESPN NBA raw JSON goes into the normalized model through pure mappers tested against the recorded fixtures, then into the same jobs and scheduler the NHL uses. After that the recap shows both leagues.

## Contract (verbatim from SESSIONS.md §S05)

**Out of scope:** API, app.

**Acceptance criteria**
1. Mapper tests for every NBA fixture with hand-read values: regular line, DNP with reason, OT game, preseason, statuses, period scores, shooting splits.
2. A test that reorders the label and stat arrays gets identical output.
3. Country mapping: "Latvia" → LVA, "Cameroon" → CMR, "USA" → USA; aliases for every spelling seen in fixtures; an unknown name → `null` + warning (tested).
4. Overrides reach NBA players: a test over the Embiid and Towns athlete fixtures yields USA and DOM with source `override`; live, after the roster job, the database shows the same (show the query).
5. NBA ingestion keeps the idempotency and stub/enrichment guarantees (tests).
6. Live, run by you: backfill a date Porziņģis played; `pnpm recap` shows NHL and NBA Latvians.
7. The season-stats job stays within the documented request budget (logged count).
8. The scheduler runs both leagues: a daily job that ran today for NHL is still due for NBA, and an NBA results run (day loop and corrections) fetches only ESPN URLs (tests).
9. `pnpm verify` green.

**Owner ruling (brainstorming, 2026-10-18):** `espn-nba/overview/3102531.json` is exempt from AC1. No mapper reads it, because season stats come from the bulk `byathlete` endpoint. It stays as S01 evidence for S13's player page.

No new dependencies. No migration.

## Module layout (mirrors `sources/nhl/`)

```
apps/server/src/sources/espn-nba/
  schemas.ts       raw zod schemas, fields we use only (z.object strips unknown keys; used keys strict)
  common.ts        parsePayload, positionGroup, toTeam, seasonFromYear / yearFromSeason, birthCountry
  games.ts         mapScoreboard(raw, gameDate)         → { games, teams, warnings }
  boxscore.ts      mapSummary(raw)                      → { lines, teams, players }
  players.ts       mapRoster(raw), mapAthlete(raw)      → { players | player, warnings }
  season-stats.ts  mapByAthlete(raw)                    → { seasonStats, page, pages, count }
  teams.ts         mapTeams(raw)                        → { teams }
  client.ts        espnUrls + fetchers (client.get → JSON.parse → mapper)
  index.ts         public surface
apps/server/src/jobs/adapters.ts  one adapter object per league, the jobs' only import from sources/
packages/shared/src/countries.ts  + name table + countryFromName
```

Errors use the NHL wording with source `espn-nba` and the endpoint named after its fixture directory, e.g. `espn-nba summary: invalid payload\n<prettified zod error>` and `espn-nba scoreboard: game 401810899: unknown status "STATUS_X"`. Builder's call: share `lookup`/`parsePayload` between the two adapters (e.g. `src/sources/common.ts`, with the source name as a parameter, same NHL messages) or keep a copy per adapter.

## Endpoints

| Endpoint | URL (`espnUrls`) | Fixtures |
|---|---|---|
| scoreboard | `site.api.espn.com/…/nba/scoreboard?dates=YYYYMMDD` | 6 recorded (incl. empty, preseason) |
| summary | `…/nba/summary?event={id}` | 3 recorded (regular, OT, preseason) |
| teams | `…/nba/teams` | **new, recorded in task 1** (`pnpm fixtures:record espn-nba teams <today>`, 1 live request) |
| roster | `…/nba/teams/{id}/roster` | `roster/9` |
| athlete | `sports.core.api.espn.com/v2/sports/basketball/leagues/nba/athletes/{id}` | 3 recorded |
| byathlete | `site.web.api.espn.com/…/statistics/byathlete?season={endYear}&seasontype={1\|2\|3}&limit=50&page={n}` | `byathlete/2026` (page 1 of 12) |

`scripts/endpoints.ts` reuses `espnUrls` wherever it builds the recorded URL exactly (`byathlete` = page 1, seasontype 2). The `teams` entry ignores its id argument.

## Mappers

**Scoreboard → games** (`events[]`: `id`, `date`, `season.{year,type}`, `status.type.name`, `competitions[0].competitors[]` `{homeAway, team.{id,abbreviation,name}, score (string), linescores?[].value}`)
- `gameDate` is the `dates=` day the caller requested (Q1). No event field carries it.
- Season: `season.year` is the end year, so `2027` → `"2026-27"` (`seasonLabel(year − 1)`).
- Season type table: `1 → PRE`, `2 → REG`, `3 → POST`. Any other type (play-in, All-Star: both unseen) skips the game with a warning. NHL treats non-league game types the same way (D-035).
- Status table (VISION §8): `STATUS_SCHEDULED → SCHEDULED`; `STATUS_IN_PROGRESS`, `STATUS_HALFTIME`, `STATUS_END_PERIOD → LIVE`; `STATUS_FINAL → FINAL`; `STATUS_POSTPONED → POSTPONED`; `STATUS_CANCELED → CANCELLED`. *My call:* an unknown name skips that game with a warning instead of throwing. This extends D-035 (NHL `gameScheduleState`), so a new ESPN status can't sink a whole night's scoreboard. Only FINAL is seen in the fixtures; every row gets a table test.
- Scores: parsed integers for LIVE/FINAL, otherwise `null`. Period scores only for LIVE/FINAL, one per `linescores` entry in order, labelled `Q1`…`Q4`, then `OT`, `2OT`, … (the label format `model.ts` documents). `endedIn` (FINAL only): more than 4 periods → `OT`, else `REG`. The NBA has no shootout.
- Teams: `toTeam(id, abbreviation, name)` with `league: 'NBA'`, `source: 'espn'`. `name` is the short name ("Warriors"), like the NHL's `commonName`.
- Public IDs: `nba-<event id>`, `nba-<athlete id>` (rule 9).

**Summary → lines, teams, players** (`header.id`, `boxscore.players[]` `{team.{id,abbreviation,name}, statistics[0].{labels, athletes[]}}`; athlete row `{athlete.{id,displayName,jersey?,position.abbreviation}, starter, didNotPlay, reason?, stats[]}`)
- **By label, never by position:** build `label → index` from `labels`. All 14 labels (`MIN PTS FG 3PT FT REB AST TO STL BLK OREB DREB PF +/-`) are required; a missing one throws, naming it. `FG`/`3PT`/`FT` `"8-13"` → made/attempted (a malformed split throws). `+/-` `"+7"`/`"-8"`/`"0"` → signed int. `MIN` is whole minutes → `minutes`. Other stats are integer strings. Output is `basketballPlayerStats` (VISION §8).
- **DNP:** `didNotPlay: true` → `played: false`, `stats: null`, `dnpReason: reason` as ESPN gives it (`"COACH'S DECISION"`, `"RIGHT FOOT"`; stored verbatim, S09 decides display case). `reason` is read **only** for DNP rows, since every played row also says `"COACH'S DECISION"` (Q6). A row with `didNotPlay: false` and a `stats` length that differs from `labels` throws.
- A player absent from the box score gets no line (Q6). `starter` comes from `starter`.
- Stubs: one per athlete row. The name splits `displayName` at the first space ("Gary Payton II" → "Gary" / "Payton II"). Also position, jersey (`null` if absent), and the box-score team as current team. Birth fields are `null`.
- Throws if the game hasn't started (no `boxscore.players`/empty), as NHL `mapBoxscore` does, so `results` only calls it for FINAL games.

**Roster → players** (`team.id`, `athletes[]` flat: `{id, firstName, lastName, jersey?, position.abbreviation, dateOfBirth?, birthPlace?.{city?,country?}}`)
- The roster names its team, so `fetchRoster(client, team)` throws if `team.id` ≠ the requested `externalId`.
- `dateOfBirth` `"1995-08-02T07:00Z"` → `"1995-08-02"` (the date part).
- Birth country through `countryFromName`. An unknown name → `null` plus a returned warning (`espn-nba roster: player <id>: unknown birth country "<name>"`).

**Athlete → player** (enrichment of box-score stubs): same fields as the roster. The current team comes from `team.$ref` (`…/seasons/2027/teams/9?…` → `"9"`); no `team` → `null`.

**Positions:** table `G → guard`, `F → forward`, `C → center` (seen), plus `PG`/`SG → guard`, `SF`/`PF → forward`. Anything else throws.

**Teams:** `mapTeams` → the 30 teams. The exact path is read from the new fixture. Expect `sports[0].leagues[0].teams[].team.{id,abbreviation,name}`.

**byathlete → season stats.** Season and type come from the response (`requestedSeason.year`, `requestedSeason.type.type`), not from the caller. Values are mapped **by `names`** (labels repeat), from each athlete's `categories[].values`, looked up by category `name` + stat name. Output is `kind: 'basketball_player'`, `basis: 'totals'`. Fields: `gamesPlayed`, `minutes`, `points`, `rebounds`, `assists`, `steals`, `blocks`, `turnovers`, `fouls`, `fgMade`, `fgAttempted`, `threeMade`, `threeAttempted`, `ftMade`, `ftAttempted` (totals), and `fgPct`, `threePct`, `ftPct` divided by 100 to the 0–1 unit (adapters.md). Per-game averages are not stored. The job re-fetches daily, so S13 can add them for free if the player page needs them.

## Countries (`packages/shared/src/countries.ts`)

- `COUNTRY_NAMES: Record<string, CountryCode>`, generated once from the same iso-codes 4.20.1 file as `COUNTRY_CODES`: each entry's `name`, `common_name` and `official_name`, inlined. "Czech Republic" (CZE's official name), "South Korea" and "United States of America" all come from this file.
- `ESPN_COUNTRY_ALIASES` keeps the spellings that aren't an ISO name: `USA`, `England`/`Scotland`/`Wales → GBR`. The `shortcut:` comment goes.
- `countryFromName(name): CountryCode | null` matches exactly, after trim, aliases first, then names. Adapters add the warning.
- Fixture spellings (roster + athletes): USA, Latvia, Nigeria, Dominican Republic, Netherlands, Brazil, Australia, Cameroon. Only `USA` needs an alias. Spellings the live roster run warns about get an alias plus a test row in the session.

## Jobs: one adapter per league (`src/jobs/adapters.ts`)

```ts
type LeagueAdapter = {
  day(client, date): Promise<{ games; teams; warnings }>;          // NHL score · NBA scoreboard
  week(client, date): Promise<{ games; teams; warnings }>;         // NHL schedule · NBA 7 × scoreboard (date … date+6)
  boxscore(client, externalId): Promise<{ lines; teams; players }>; // NHL boxscore · NBA summary
  player(client, externalId): Promise<{ player; warnings }>;       // NHL landing · NBA athlete
  teams(client, date): Promise<{ teams }>;                         // NHL schedule-calendar · NBA teams (date unused)
  roster(client, team): Promise<{ players; warnings }>;
  seasonStats(client, season, seasonType): Promise<SeasonStats[]>; // NHL skater+goalie · NBA all byathlete pages
};
export const ADAPTERS = { NHL: …, NBA: … } satisfies Record<League, LeagueAdapter>;
```

Every job calls `ADAPTERS[args.league]` instead of `sources/nhl` directly. All `arrives in S05` guards go: `schedule`, `roster`, `season-stats`, both in `results` (the day loop and the corrections pass), `parseJobArgs` (`--league nba` accepted; valid: nhl, nba) and `inspect`. The job algorithms stay as they are (D-037, D-039, D-040). The NBA schedule makes 7 scoreboard requests (one per day, because the date is the game day). ESPN has no week endpoint that keeps the date.

**NBA season stats and request budget.** `seasonStats` fetches page 1, then pages 2…`pagination.pages`, for each season type of the current season that has a started game (the NHL rule). It throws if `pages` > 20 (`espn-nba byathlete: <n> pages exceeds the budget of 20`) or if the rows collected < `pagination.count` (truncated). The budget is ~12 requests per season type at 578 players, a cap of 20, and at most 3 types (≤ 60 a day, ~12–25 normally). It goes into `docs/sources/espn-nba.md`. The job logs `counts.requests` as today. `seasontype=1` (preseason) is unverified until the live run, because today, 2026-10-18, is preseason.

**Overrides (AC4):** the roster job and the results enrichment already pass `ctx.overrides` to `upsertPlayers`. The test writes the mapped Embiid and Towns athlete fixtures through `upsertPlayers` with the committed overrides file, then reads `nationality`/`nationality_source` back.

## Scheduler for two leagues

- `job_runs.args` already stores `league` (jsonb), so **no migration**. `loadState` groups by `job` and `args->>'league'`. `SchedulerState.lastRuns` becomes `Partial<Record<League, Partial<Record<JobName, Date>>>>`, and `dailyDue(league, job)` reads its league's entry. The `decide.ts:26` `shortcut:` goes.
- `main.ts` passes `['NHL', 'NBA']` (`leagueSchema.options`) to `startScheduler`. Decisions stay per league, in run order (NHL first). The runner's in-process lock stays per job name: a tick runs its decisions one after another.

## Inspect and recap

- `pnpm inspect espn-nba <endpoint> <id>` for `scoreboard` (the id is the date and becomes `gameDate`), `summary`, `teams`, `roster`, `athlete`, `byathlete`.
- `pnpm recap` already formats basketball lines and groups by league. It gets a test with one NHL and one NBA game on the same day.
