## `upcoming` rows (server + contract)

**Rule** (`apps/server/src/game-day-rows.ts`, a new `DayRow` kind `'upcoming'`). For each shown player (`isShown`, so the selection rule decides: hidden never, favorites from any country yes, league filter applies) with no line in this game, take his current team in this game (none → no row) and check D-038's guard (a line in any game that day → no row). Then:
- FINAL with its box score stored → `not-in-lineup` (unchanged);
- no box score stored and status SCHEDULED, LIVE or FINAL → `upcoming`;
- anything else (POSTPONED, CANCELLED) → no row.

The game then has rows, so `dayGames` already sorts it into the first group by start time. `rank()` gives `upcoming` `[4, 0]`. Upcoming rows never share a game with lines (only FINAL games get box scores), so within a game they're ordered away team first, then by public ID, like every other tie.

**Contract** (`packages/shared/src/contract/responses.ts`): `playerRowSchema` gains `z.object({ type: z.literal('upcoming'), side, player: playerRef })`. No extra fields: the text follows the game's `status`, which the game already carries. `playerRow` in `api/day.ts` gets the case. `/v1/games/{id}` returns the same rows for a game without a box score (it builds on `dayGames`).

**Recap** (`apps/server/src/recap.ts`): `rowText` becomes an exhaustive `switch` over the row kind and takes the game; upcoming → the status text above.

**Tests that change (D-049):** `game-day-rows.test.ts` "no not-in-lineup row when the game isn't FINAL" (LIVE → now one `upcoming` row) and "no not-in-lineup row for a FINAL game whose box score isn't stored" (→ one `upcoming` row).

**New tests.** Unit (`game-day-rows.test.ts`): SCHEDULED, LIVE, FINAL-without-box-score each give `upcoming`; POSTPONED and CANCELLED give none; a line in another game that day gives none. Recap (`recap.test.ts`): each status's upcoming text, and a recap prints an upcoming row. API (`api-upcoming.test.ts`, criterion 4) over the real jobs and fixtures:
- 2026-03-24: the existing seed's NHL week is stored from the schedule, so every game is FINAL without a box score. `seedApiDb()` plus a results run for 2026-03-24 that stores only the recorded box score `2025021127` (MIN@TBL; the other box scores 404, so the run is `partial` and those games stay without one). With `countries=LVA`: Silovs (PIT) gets `upcoming` in COL@PIT, Vilmanis and Balinskis (FLA) in SEA@FLA, and `pnpm recap`'s formatter prints "Waiting for stats". Girgensons (current team CBJ in the seed) has a line for TBL in MIN@TBL, so he gets no row in CBJ@PHI. `fav=` Rust (PIT, USA) gets one; `hide=` Silovs removes his; the LVA free agent (no team) gets none; MIN@TBL keeps Girgensons' line row.
- 2026-10-16: the recorded `nhl/score/2026-10-16-states` (PIT@COL `FUT`, BOS@ANA `FUT`) stored by the results job → Silovs `upcoming` in PIT@COL, which sorts before BOS@ANA. A live case: the same fixture with PIT@COL's `gameState` set to `LIVE` and both scores set, built in memory like `api-seed.ts`'s `score()` (the file isn't touched), in its own DB.
- Existing tests keep passing: 2026-01-17 (lines + Girgensons "Not in lineup"), 2026-03-23 (Leons DNP).
These days are not added to `seedApiDb()` itself: a 2026-10-16 game would move `/v1/meta`'s NHL season in the other API tests (their clock is 2026-10-18). The extra seeding is an exported helper in `test/api-seed.ts` that `screenshot-api.ts` reuses.

## Shared formatting (`packages/shared/src/format.ts`, new)

One place for the card text, so the recap and the app can't drift (D-038's ruling). Pure, tested in `packages/shared/test/format.test.ts`:
- `toi(seconds)` → `18:32`; `savePct(0.9333)` → `.933`, `1` → `1.000`; `signed(n)` → `+2`, `0`, `-1`.
- `lineText(line)` → `string[]` for `{ kind, stats }` (both the server's played `StatLine` and the contract's line fit):
  - skater: `["1 G · 1 A · +2 · 4 SOG · 18:32"]`
  - goalie: `["28/30 · .933 · 2 GA · W"]` (no save % or no decision → that part left out)
  - basketball: `["22 PTS · 7 REB · 5 AST · 29 MIN", "FG 7-17 · 3PT 2-6 · FT 6-7"]`
- `finalLabel(endedIn)` → `Final`, `Final/OT`, `Final/SO`.
- `upcomingText(status)` → `Not started` / `In progress` / `Waiting for stats` (POSTPONED, CANCELLED → the status label; the server never sends those).

The recap's `card()` becomes `lineText(line).join(' · ')`, so its output (and its tests) stay as they are.

## App (`apps/mobile`)

### Formatting (`src/lib/format.ts`, pure, tests in `apps/mobile/test/format.test.ts`)
- `startTime(iso, gameDate, locale?, timeZone?)`: `Intl.DateTimeFormat(locale, { timeStyle: 'short', timeZone })` (only timeStyle gives both test examples below); the app passes neither locale nor zone, so the device decides the zone and 12/24 h. A night stays on its US game day, so a start on another local date gets the local short weekday in front (owner, after the Android check 2026-10-21). Tests: `2026-10-17T01:00:00Z`, `en-GB`, `Europe/Riga` → `04:00` on game day 2026-10-17 and `Sat 04:00` on 2026-10-16; `en-US`, `America/New_York` → `9:00 PM` on 2026-10-16 and `Fri 9:00 PM` on 2026-10-17.
- `dayLabel('2026-03-16')` → `Mon, Mar 16` (English, the date read as a calendar day, never shifted by the zone).
- `statusLabel(game, locale?, timeZone?)`: FINAL → `finalLabel`, LIVE → `Live`, SCHEDULED → `startTime`, POSTPONED → `Postponed`, CANCELLED → `Cancelled`.
- `scoreText(game)`: `CBJ 3 – 2 PIT` when both scores exist, else `CBJ @ PIT` (the recap's format).
- `rowText(row, status)` → `string[]`, an exhaustive switch over `row.type`: line → `lineText`; dnp → `DNP — Coach's decision` (the reason in sentence case; ESPN sends `COACH'S DECISION`) or `DNP`; not-in-lineup → `Not in lineup`; upcoming → `upcomingText(status)`.
- `latestDate(meta, leagues)`: the latest `latestGameDate` among the selected leagues, `null` if none.
- `rowLabel(row, status, team)`: screen-reader text built from the row's stats with the abbreviations spelled out (goals, assists, shots on goal, goals against, points, rebounds, assists, minutes, field goals, three-pointers, free throws, win/loss/overtime loss, did not play), used as the row's `accessibilityLabel`.

### Text and states (in this priority)
1. **Loading** (no meta or day data yet): the stepper's place plus three grey card-shaped blocks (`border` colour on `surface`).
2. **Error with no data:** the existing `ErrorState` full screen ("Can't reach the server…" / "The server had a problem…") with Try again (refetches meta and day).
3. **No game day at all** (no selected league has a `latestGameDate`): "No games yet."
4. **Day with no games:** "No games on Tue, Mar 17."
5. **Nothing followed** (no countries and no favorites): "You're not following any countries or players yet." + `Open Settings`. Then the games under Other games.
6. **No rows, day after the latest game day of the selected leagues:** "None of your players play on Sat, Oct 11." + `Next game day` (when there is one). Then Other games.
7. **No rows, otherwise:** "None of your players played on Mon, Mar 16." + `Previous game day` (when there is one). Then Other games.
8. **Rows:** the shown games, then Other games.

**Banner** (above the list, when data is on screen): a refetch that failed → "Couldn't refresh — showing saved data."; on web while offline (`fetchStatus === 'paused'`) → "You're offline — showing saved data." No NetInfo: on Android an offline refetch simply fails, which shows the first banner (closes S08's `shortcut:` question).

### Data fetching and caching
- `useMeta()`: key `['meta']`. `useDay(date, prefs)`: key `['day', date, leagues, countries, favorites, hidden]` (the stored, sorted lists), `enabled` once the date is known, calling `api.day(date, toPrefs(prefs))`.
- QueryClient stays `retry: 1`, `staleTime` 5 min, in memory (`shortcut:` comment pointing at the v2 item).
- **Focus:** `_layout.tsx` wires TanStack Query's `focusManager` to `AppState` (web already uses `visibilitychange`), so coming back to the app refetches stale meta and day: in the morning the latest day moves forward by itself when no `date` is set.
- **Pull to refresh:** `RefreshControl` refetches meta and day together; its spinner shows only for that pull, not for focus refetches. Web has no pull gesture: focus and reload cover it.
- A preferences change changes the key, so the day refetches when you come back from Settings.
