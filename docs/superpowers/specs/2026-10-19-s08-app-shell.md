# S08 — App shell, settings, screenshot tooling: design

Session S08, branch `s08-app-shell`. Spec: `docs/SESSIONS.md` §S08; VISION §4.2 (Settings) and §4.6 (UI principles); area rules `.claude/rules/mobile.md` and `tests.md`. The app gets its skeleton, the preferences store, the Settings screen and `pnpm screenshots`, so Claude can see the UI. Today and Search stay placeholders.

## Contract (verbatim from SESSIONS.md §S08)

**Out of scope:** Main page content (S09), search and favorites (S12), player and game pages (S13).

**Acceptance criteria**
1. A fresh install defaults to Latvia + both leagues; preferences survive a web reload and an Android relaunch.
2. Preferences store logic is unit-tested (pure reducer-style functions).
3. `pnpm screenshots` produces PNGs; Claude looks at them and fixes visible layout problems (show before/after in the session).
4. Runs on Android (Expo Go, talking to the dev API over the LAN) and web without errors; API down → friendly error.
5. `pnpm verify` green.

Also out of scope: Favorites/Hidden lists in Settings (S12; the store already holds the two lists, empty), the privacy-policy link (no URL exists until S11/S15 → parking lot), offline caching of server data (S09's "last cached data with a banner"), tab icons.

## Owner decisions (brainstorming, 2026-10-19)

## Theme tokens (`src/theme.ts`)

```ts
colors: { background, surface, text, textMuted, border, accent, onAccent, danger }   // light + dark sets
space:  { xs: 4, sm: 8, md: 12, lg: 16, xl: 24 }
font:   { caption: 13, body: 16, title: 20 }   // sizes; Text keeps allowFontScaling (system font scale)
radius: 12
useTheme() → tokens for useColorScheme() ('dark' → dark, anything else → light)
```

The system color scheme decides (VISION §4.6: "follow the system"; `app.json` already has `userInterfaceStyle: automatic`). Components style only through `useTheme()`, with no literals. The navigation theme (tab bar, headers) is built from the same tokens. The exact palette is the builder's: neutral greys, one accent, contrast ≥ 4.5:1 for text in both sets.

## Preferences store (`src/state/`)

Pure module `prefs.ts` (no React or storage imports, so Vitest can test it):

```ts
type StoredPrefs = {
  leagues: League[];          // sorted, unique, never empty
  countries: CountryCode[];   // sorted, unique, may be empty (owner)
  favorites: PublicId[];      // [] until S12
  hidden: PublicId[];         // [] until S12
};
DEFAULT_PREFS: StoredPrefs = { leagues: ['NBA', 'NHL'], countries: ['LVA'], favorites: [], hidden: [] }
toggleLeague(p, league): StoredPrefs    // turning off the last league returns p unchanged
toggleCountry(p, code): StoredPrefs     // add/remove, result stays sorted
toPrefs(p): Prefs                       // the Sets that shared's selection rule and createApiClient take
```

Updates return a new object, or the same one when nothing changes. Arrays stay sorted, so equal preferences serialize equally.

Store `prefs-store.ts`: `usePrefs = create(persist(…))` with state `StoredPrefs` + actions `toggleLeague(l)` / `toggleCountry(c)` that call the pure functions. Persist options: `name: 'prefs'`, `version: 1`, `storage: createJSONStorage(() => AsyncStorage)`, `partialize` to the four lists. On disk it is one object, `{ state: StoredPrefs, version: 1 }` (VISION §4.2). There is no `migrate` until a version 2 exists. AsyncStorage uses `localStorage` on web.

Rehydration is checked (my call: storage is outside the app's control, and bad prefs would turn every S09 request into a 400). Pure `restorePrefs(stored: unknown): StoredPrefs` in `prefs.ts` parses with a zod schema (leagues from `leagueSchema`, ≥ 1; countries from `countryCodeSchema`; favorites/hidden from `publicIdSchema`), then sorts and dedupes. Anything invalid → `DEFAULT_PREFS`. The store's `merge` option calls it. Tested.

## Server data (`src/api/`)

- `client.ts`: `export const api = createApiClient(apiUrl, fetch)`, with `apiUrl = (process.env.EXPO_PUBLIC_API_URL ?? 'http://localhost:3001')` minus any trailing slash (the client needs none); that one-liner is pure `apiBaseUrl(env)` in `src/lib/api-url.ts`, tested. Expo inlines `EXPO_PUBLIC_*` at build time. `apps/mobile/.env` sets it for a phone, and `apps/mobile/.env.example` shows the LAN form.
- `queries.ts`: `useCountries()` → `useQuery({ queryKey: ['countries'], queryFn: () => api.countries(new Set(['NBA', 'NHL'])) })`. It always asks for both leagues (my call). The list then doesn't change when a league is toggled, and each row shows both counts. Query keys of later prefs-dependent hooks include `toPrefs` lists (rule); this one has no prefs input.
- `QueryClient` defaults: `retry: 1` (my call; the default 3 with backoff makes "API down" take ~7 s to show), `staleTime: 5 min`.

## Settings screen (`settings.tsx`)

One `ScrollView` with three sections, each a titled card:

1. **Leagues:** two rows, "NHL" and "NBA", each with a `Switch`. When only one is on, its switch is disabled and a caption says "At least one league stays on."
2. **Countries:** the title row shows "n selected". Below it are a search `TextInput` ("Search countries") and the rows. A row shows the code (bold, fixed width), the English name (`countryName(code)`, see below), the counts ("NHL 6 · NBA 1", a league left out when 0) and a ✓ when selected. Tapping the row toggles it (`accessibilityRole="checkbox"`, `aria-checked` — react-native-web ignores `accessibilityState` — and label "Latvia"; the state is announced from `aria-checked`, so the label doesn't repeat it (owner, after the final review)). No flag emoji: shared has no alpha-2 mapping, and codes are what VISION requires anyway.
   - Display name (my call): new `countryName(code)` in `packages/shared/src/countries.ts` (exported, tested there), = the shortest of that code's names in `COUNTRY_NAMES` (Debian iso-codes: name, common_name, official_name), ties → alphabetical. So LVA → "Latvia", KOR → "South Korea", CZE → "Czechia", USA → "United States", GBR → "United Kingdom", RUS → "Russian Federation". It lives in shared because S13's player page (birthplace) needs it too. A code with no name → the code itself.
   - Rows come from pure `countryRows(response, selected, query)` in `src/lib/countries.ts`: selected countries first (a selected country missing from the response still shows, with no counts, so it can be unticked), then the rest by total players descending, then display name. Search (my call): the trimmed query is a substring of the code or of the display name, case- and diacritic-insensitive ("sw" → Sweden, Switzerland, and Eswatini too; "lat" → Latvia). Other names aren't searched: "cze" finds Czechia. An empty query → every row. Tested.
   - With 0 selected, a caption reads "No countries selected — Today stays empty until you pick one."
   - States: loading → spinner. Error → friendly message + "Try again" (refetch). Offline (`fetchStatus === 'paused'`, which TanStack Query reports on web when the browser is offline) → "You're offline. Countries load when you're back online." On Android, TanStack Query can't tell it's offline without NetInfo (a new dependency, my call: no). An offline phone gets the network-failure message ("Can't reach the server. Check your connection…"), which covers it. `shortcut:` comment, add NetInfo if S09's offline banner needs it on Android. No match → "No country matches "…"."
3. **About:** "Our Players", version (`expo-constants` `expoConfig.version`), "Data from the public NHL and ESPN web APIs.", "Not affiliated with the NHL or NBA."

Friendly error text comes from pure `errorMessage(error)` in `src/lib/errors.ts` (tested). An `ApiError` → "The server had a problem. Try again in a moment." Anything else (a network failure, a refused connection) → "Can't reach the server. Check your connection and try again." The raw error is never shown. One `ErrorState` component (`src/components/`) renders it with the retry button. S09 reuses it.

## Web output

`app.json` `web.output: "server"` → `"single"` (my call, a parking-lot item since S00). `"server"` needs a Node host, and `"static"` pre-renders in Node, where persisted prefs aren't available, so the first paint would show defaults. A single-page build is a static `dist/` (S14's home-screen web app needs exactly that) and renders only in the browser.

## `pnpm screenshots`

Root script → `pnpm --filter @our-players/mobile screenshots` → `tsx scripts/screenshots.ts`. It runs on its own ports, so it works while `pnpm dev:server`/`dev:mobile` run:

1. **API:** spawns `apps/server/scripts/screenshot-api.ts` (new; the server package owns it, because `apps/mobile` must not import the server). It boots `createApp` over in-memory PGlite seeded by `seedApiDb()` (the test seed: real ingestion over recorded fixtures, so the output is deterministic and never touches the owner's dev DB) on `:3101`, with `corsOrigins: ['http://localhost:8091']`. The script waits for `/health`.
2. **Build:** `expo export -p web --output-dir .screenshots/web` with `EXPO_PUBLIC_API_URL=http://localhost:3101`.
3. **Serve:** `expo serve` on `:8091` (the builder checks its flags; if it can't serve a single-page build, a ~20-line `node:http` static server with an `index.html` fallback).
4. **Capture:** Playwright Chromium at phone size (412×915, deviceScaleFactor 2), one context per `colorScheme` (`light`, `dark`), each in a fresh context, so a fresh install. Shots, as `apps/mobile/.screenshots/<scheme>-<name>.png`:
   - `today`, `search` (placeholders)
   - `settings` (top: leagues + start of the countries list)
   - `settings-search` (typed "sw" into the country search)
   - `settings-about` (scrolled to About)
   - `settings-api-down` (`page.route('http://localhost:3101/**', r => r.abort())` → the friendly error)
5. Kills both child processes in `finally`; any step failing exits non-zero with the step named.

Browser: `PLAYWRIGHT_CHROMIUM_PATH` → `executablePath` when set (Arch: `/usr/bin/chromium`). Otherwise Playwright's bundled Chromium, installed once with `pnpm --filter @our-players/mobile exec playwright install chromium` (no `--with-deps`). Both are in the README. CI doesn't run it. `.screenshots/` is already gitignored.

## Proving criteria 1 and 4

- **AC1 on web:** a one-off Playwright run in the session against the same build: fresh context → NHL+NBA on, LVA ticked; untick NBA and tick SWE, reload, both still set. Its output gets pasted. **Android:** owner step (toggle, kill Expo Go, reopen).
- **AC4:** web via the screenshots (api-down shot) plus the dev API live. **Android:** owner step with `EXPO_PUBLIC_API_URL=http://<LAN-IP>:3001` (README). `main.ts` calls `serve()` without a hostname, so Node listens on all interfaces: no server change. Native fetch ignores CORS.
