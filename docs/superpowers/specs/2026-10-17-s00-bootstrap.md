## Version pinning
- **Node 24.22.0** (latest 24 LTS, 2026-10-14) in `.tool-versions`. mise always reads that file. Its idiomatic files (`.nvmrc`/`.node-version`) are off on this machine. `actions/setup-node` reads it with `node-version-file`.
- **pnpm 12.14.0** in `packageManager` (with corepack's hash, written by `corepack use`). Corepack and pnpm's own version switching both honor it. CI and the cloud hook run `corepack enable`.
- `engines.node: ">=22.13"` in the root `package.json`. *My call:* the spec says `>=22`, but Expo SDK 58's CLI requires `^22.13.0 || ^24.3.0` and Vitest 5 requires `^22.12.0`, so the honest floor is 22.13.
- **CI matrix** `node: [22, 24]`: the 24 leg reads `.tool-versions`, so it runs exactly the pinned version. The 22 leg uses the latest Node 22, as cloud sessions do.

## Shared TypeScript as source
`packages/shared/package.json` sets `"exports": { ".": "./src/index.ts" }`, so there's no build step and no `dist`. Each consumer transpiles the source itself: Metro (expo/metro-config's automatic monorepo support, no `metro.config.js`), tsx on the server, Vite inside Vitest, and `tsc` follows the export into the source. The server declares the dependency but doesn't import it yet; a one-off `tsx` command proves it resolves.

## Config files
- `tsconfig.base.json`: `strict`, `noUncheckedIndexedAccess`, `skipLibCheck`, `noEmit`. Shared and server extend it with `module`/`moduleResolution` `bundler` and `target` ES2023. Mobile extends `["expo/tsconfig.base", "../../tsconfig.base.json"]`.
- `biome.json`: recommended lint rules; formatter with 2 spaces, single quotes, line width 100 (matching the existing hooks); respects `.gitignore` and also skips `**/test/fixtures/**`, `.data`, `.expo`, `dist`. *My call:* the existing `.claude/hooks/*.mjs`, `.claude/settings.json` and `nationality-overrides.json` are in reach and get a one-time reformat in this session (whitespace and quotes only).
- `vitest.config.ts`: one root config that includes `{apps,packages}/*/{src,test}/**/*.test.{ts,tsx}`, with no per-package projects.
