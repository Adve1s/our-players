# S02b — Database schema and repositories: design

Session S02b, branch `s02b-database`. Spec: `docs/SESSIONS.md` §S02b. The Postgres schema per VISION §8 in Drizzle, three ways to open it (dev PGlite on disk, test PGlite in memory, node-postgres when `DATABASE_URL` is set), and repositories that store S02a's normalized model idempotently. Repositories and the nationality recomputation are written test-first.

## Contract (verbatim from SESSIONS.md §S02b)

**Out of scope:** adapters, jobs, API, app.

**Acceptance criteria**
1. `pnpm db:migrate` succeeds on a fresh local DB, and `pnpm db:generate` right afterwards produces no new migration.
2. Writing the same normalized game and lines twice leaves identical rows (PGlite test).
3. Invalid stat payloads are rejected on write with a clear error.
4. Nationality recomputation (PGlite tests): stored players get their nationality and its source from the resolver; an override whose player isn't in the DB, or whose name doesn't match the stored name, logs a warning.
5. `pnpm verify` green.

## Schema (VISION §8)
Enums are `pgEnum`s built from the shared zod enums' `.options`, so the DB rejects a value the model doesn't know: `league`, `sport`, `source`, `game_status`, `season_type`, `ended_in`, `stat_kind`, `position_group`, `nationality_source`, plus two new ones defined in the schema: `stat_basis` (`totals`, `per_game`) and `job_status` (`running`, `succeeded`, `failed`, `partial` — VISION §6.1 says a roster run records a partial failure). Surrogate keys are `integer … generated always as identity`. Timestamps are `timestamptz`; dates (`game_date`, `birth_date`) are `date` read as `'YYYY-MM-DD'` strings.

| Table | Key / unique | Other columns | Indexes |
|---|---|---|---|
| `leagues` | PK `code` | `sport`, `name` | — |
| `teams` | PK `id`; unique (`source`, `external_id`) | `league` → leagues, `abbrev`, `name`, `updated_at` | — |
| `players` | PK `id`; unique `public_id` | `league` → leagues, `first_name`, `last_name`, `search_name`, `position`, `position_group`, `current_team_id` → teams (null), `jersey`, `birth_date`, `birth_city`, `birth_country`, `nationality`, `nationality_source`, `active` (default true), `updated_at` | `nationality` (the country filter) |
| `player_external_ids` | PK (`source`, `external_id`) | `player_id` → players | `player_id` |
| `games` | PK `id`; unique `public_id`; unique (`source`, `external_id`) | `league`, `season`, `season_type`, `game_date`, `start_time_utc`, `status`, `home_team_id`/`away_team_id` → teams, `home_score`, `away_score`, `period_scores` jsonb, `ended_in`, `final_at`, `boxscore_fetched_at`, `corrected_at`, `updated_at` | (`league`, `game_date`) — the game-day view |
| `stat_lines` | PK (`game_id`, `player_id`) | `team_id` → teams, `kind`, `played`, `dnp_reason`, `starter`, `stats` jsonb (null when not played), `updated_at` | `player_id` — the game log |
| `season_stats` | PK (`player_id`, `season`, `season_type`, `kind`) | `basis`, `stats` jsonb, `fetched_at` | — |
| `job_runs` | PK `id` | `job`, `args` jsonb, `started_at`, `finished_at`, `status`, `counts` jsonb, `error` | — |

- `final_at`, `boxscore_fetched_at`, `corrected_at` exist but no S02b code writes them: they are ingestion bookkeeping that S04a's jobs set.
- **Leagues are seeded by `migrateDb()`**, not by a migration (migrations are generated, never hand-edited): it inserts NHL/hockey and NBA/basketball with `on conflict do nothing` after applying the migrations.

## DB clients
One type for every repository: `Db = PgDatabase<PgQueryResultHKT, typeof schema>`, the base both drivers extend.

| | How it opens | Where |
|---|---|---|
| dev | `openDb()` without `DATABASE_URL` → PGlite on disk | `apps/server/.data/pglite/` (gitignored) |
| test | `createTestDb()` → PGlite in memory, `migrateDb()` applied | per test; `close()` in `afterEach` |
| prod | `openDb()` with `DATABASE_URL` → node-postgres `Pool` | the deploy's Postgres (S10) |

`openDb()` returns `{ db, close }`. `migrateDb(db)` runs Drizzle's migrator over `apps/server/drizzle/` and seeds the leagues; it is the same code in all three. Scripts:
- `pnpm db:generate` → `drizzle-kit generate` (reads only the schema, no DB).
- `pnpm db:migrate` → `tsx src/db/cli.ts migrate`: `openDb()` + `migrateDb()`. Using our own script rather than `drizzle-kit migrate` keeps one code path for PGlite and Postgres, and it also seeds.
- `pnpm db:reset` → `cli.ts reset`: refuses when `DATABASE_URL` is set (local only, per CLAUDE.md), deletes `.data/pglite/`, then migrates.

PGlite on disk is single-process: two processes opening `.data/pglite/` at once can corrupt it. `shortcut:` one process at a time (`pnpm db:migrate` with the dev server stopped); S04a, which adds `pnpm job`/`pnpm recap` next to `pnpm dev:server`, settles it (e.g. jobs run inside the dev server, or a lock). The node-postgres path is typechecked but not exercised before S10 (no Postgres in CI or tests); my call, and a `shortcut:` comment marks it.

## Repositories
Every function takes `db` first and the normalized model from `packages/shared`, writes in one statement or one transaction, and returns how many rows it inserted or changed (S04a puts that in `job_runs.counts`). Empty input writes nothing.

| Function | Natural key (conflict target) | References resolved |
|---|---|---|
| `upsertTeams(db, teams)` | (`source`, `external_id`) | — |
| `upsertPlayers(db, players, overrides)` | `public_id`; external ID by (`source`, `external_id`) | `currentTeamExternalId` → team by (player's `source`, ID) |
| `upsertGames(db, games)` | `public_id` | home/away team by (game's `source`, ID) |
| `upsertStatLines(db, gamePublicId, lines)` | (`game_id`, `player_id`); the game's other lines are deleted | game and player by public ID; team by (game's `source`, `teamExternalId`) |
| `upsertSeasonStats(db, rows)` | (`player_id`, `season`, `season_type`, `kind`) | player by public ID |
| `startJobRun(db, job, args)` → `id` / `finishJobRun(db, id, { status, counts, error })` | insert-only, by `id` | — |

- **Idempotent means a no-op, not a rewrite.** Each upsert is `insert … on conflict (key) do update set <columns> = excluded.<columns>, updated_at = now() where (<columns>) is distinct from (excluded.<columns>)`. A repeat write changes no row, not even `updated_at`, so AC 2's "identical rows" holds literally and the second call returns 0. `src/db/upsert.ts` builds that clause once. `season_stats.fetched_at` follows the same rule (the time these values were stored); feed freshness belongs to `job_runs`.
- **Bookkeeping timestamps use the database's `now()`** (`updated_at`, `fetched_at`, `started_at`, `finished_at`); my call. They feed no logic in S02b, and the jobs that make time-based decisions (S04) inject their clock for those.
- **Unknown references fail loudly**: a team, game or player ID that isn't stored throws an error naming it (`unknown team nhl/22`, `unknown player nhl-8478402`). S04a stores stub players before their lines (VISION §6.1).
- **A game's lines are written as one set** (my call): a box score lists every player of the game, so `upsertStatLines` takes one game's complete lines and, in the same transaction, deletes that game's stored lines for players no longer in it. A corrected box score (S04b) that drops a player or moves him to the other team leaves no stale line. Deleted rows count as changed.
- **Records are complete** (my call): every column is overwritten with the incoming value, nulls included. Callers pass whole normalized records; S04a's box-score stubs are only for players not yet stored, so they never overwrite a richer row.
- **Stat lines are validated before anything is written** (AC 3): each played line goes through `parseStatPayload(kind, stats)`; a non-played line must have `stats: null`; the line's `kind` must belong to the game's sport (`hockey_*` for NHL, `basketball_player` for NBA) and its team must be the game's home or away team (my call: both are cheap once the game is looked up). The error names the line: `stat line nhl-2026020001/nhl-8478402: invalid hockey_skater stats: ✖ …`. One bad line rejects the whole batch.
- **`upsertPlayers` computes nationality on write** with `resolveNationality` and the given overrides (what `model.ts` promises: "computed on store"), so a new player is never stored without one. It also sets `search_name` = `searchName(firstName + ' ' + lastName)`: lowercase, NFD with combining marks removed (`Porziņģis` → `porzingis`). `shortcut:` letters that don't decompose (ø, ł, đ) stay as they are; upgrade when S07's search needs them. It doesn't touch `active` (the roster job's rule, S04a).

## Nationality recomputation
`recomputeNationalities(db, overrides) → { updated, warnings }` — for when the overrides file changes (the roster job, S04a, runs it after upserting players).
1. Reads every stored player's `public_id`, `birth_country`, `search_name`, `nationality`, `nationality_source`.
2. Applies `resolveNationality` to each; updates (in one transaction) only the rows whose nationality or source changes, with `updated_at`. An override removed from the file reverts its player to the birth country.
3. For each override: no stored player with that public ID → warning `nationality override nba-3059318 (Joel Embiid): player not in the database`; stored name differs → warning `nationality override nba-3059318: name "Joel Embiid" does not match stored "Joel Embid"`. Names compare by `searchName`, so case and diacritics don't warn (ESPN spells Porziņģis without them); my call.
4. Each warning goes to `console.warn` and into the returned `warnings` (the job puts the count in `job_runs`). There is no logger yet; S10 adds log hygiene.

## Tests (red/green: the test-writer writes them against stubs)
Every test opens `createTestDb()`. Test data is small hand-written normalized objects (two teams, a few players, one game per league), not fixtures: adapters arrive in S03.

| AC | Test |
|---|---|
| 1 | Owner-visible command output: `rm -rf apps/server/.data && pnpm db:migrate && pnpm db:generate` ("No schema changes"). `createTestDb()` applying the migrations is exercised by every test below. |
| 2 | Writing the same teams, players, game and stat lines twice: every table's rows are deep-equal after the second write (including `updated_at`), and the second write returns 0 changed rows. |
| 2 | A changed score or stat line is updated in place (one row, new values, newer `updated_at`); a changed season-stats row likewise. |
| 2 | Re-writing a game's lines without one player deletes that player's line; other games' lines are untouched. |
| 2 | Teams, players (+ external IDs) and season stats written twice are unchanged; same for a hockey and a basketball game. |
| 3 | An invalid payload of each kind (missing field, negative count, unknown key) is rejected; the error names the game, player and kind; no line of the batch is stored. A non-played line with stats, a played line without, a hockey kind on an NBA game and a team that isn't playing in the game are rejected. |
| — | A line, player or game referring to an unknown game, player or team throws naming the ID. |
| 4 | Recompute: birth country → (`LVA`, `birth`); an override → (override, `override`); no birth country → (`null`, `null`); a removed override reverts to the birth country; a second run updates nothing. |
| 4 | Warnings: override for a player not stored → warning naming the ID; stored name differs → warning naming both names; same name with different case/diacritics → no warning; each warning is also passed to `console.warn`. |
| — | `upsertPlayers` stores the resolver's nationality and the diacritic-free `search_name`. |
| — | `startJobRun` / `finishJobRun` store a run with its args, status, counts and error. |
| 5 | `pnpm verify` output. |
