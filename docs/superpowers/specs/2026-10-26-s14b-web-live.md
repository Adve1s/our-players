# S14b — Web go-live — design

Spec: `docs/SESSIONS.md` §S14b. Goal: PC users open the web app in a browser; iPhone friends add it to their home screen. S14a built and checked everything locally (`docs/superpowers/specs/2026-10-23-s14a-web-build.md`, "What S14b switches on"); this session puts it online at **`https://ourplayers.adveis.dev`**.

## Contract (quoted from §S14b)

**Out of scope:** new features.

**Acceptance criteria**
1. Deployed URL works on desktop and iPhone Safari; added to the home screen it opens standalone with the right icon (you, or your iPhone friend).
2. Deep links work on reload on the host.
3. Production API accepts the web origin and rejects others.
4. `pnpm verify` green.

## Where it lives: the custom domain only (Claude's call)

The owner bought `adveis.dev` in S10b (DNS on Cloudflare), so the site goes straight to `ourplayers.adveis.dev` as a Workers Custom Domain, set in `apps/mobile/wrangler.jsonc`:

- `"routes": [{ "pattern": "ourplayers.adveis.dev", "custom_domain": true }]`: on deploy, Cloudflare creates the DNS record and the certificate itself. No DNS step in the console; nothing may already exist at that name (checked: `getent hosts ourplayers.adveis.dev` finds nothing).
- `"workers_dev": false` (explicit; it is also the default once `routes` exists): no second address. A `workers.dev` copy would be a broken site, because the API only allows `https://ourplayers.adveis.dev`, and adding it to `CORS_ORIGINS` buys nothing.

Recorded as D-061.

## The production API URL in the build

Unchanged from S14a: the workflow takes `EXPO_PUBLIC_API_URL` from the repo variable `WEB_API_URL` and fails before building unless it starts with `https://`. Value: `https://api.ourplayers.adveis.dev` (DEPLOY.md §9). Claude sets it with `gh variable set` (not a secret: it ends up in the public bundle).

## The deploy workflow switched on

`.github/workflows/deploy-web.yml`:
- `on:` gains `push: branches: [main]` with `paths:` `apps/mobile/**`, `packages/shared/**`, `pnpm-lock.yaml` (a dependency bump changes the bundle) and `.github/workflows/deploy-web.yml`. `workflow_dispatch` stays (redeploy by hand). The job's `if: github.ref == 'refs/heads/main'` stays.
- `WRANGLER_SEND_METRICS: false` on the wrangler step (S14a's note).
- Wrangler stays `pnpm dlx wrangler@4.151.3`.

Merging this PR changes `apps/mobile/**`, so the merge itself triggers the first CI deploy.

## The first deploy, before the merge (Claude's call)

The workflow deploys only `main`, but the phone test happens in this session. So the first deploy runs from the laptop, on this branch, through the same wrangler version:
1. Owner: `wrangler login` (Claude starts it; the owner clicks Allow in the browser).
2. Claude: `EXPO_PUBLIC_API_URL=https://api.ourplayers.adveis.dev pnpm build:web`, then `pnpm dlx wrangler@4.151.3 deploy` in `apps/mobile`, after the owner says go. This creates the Worker and the custom domain.
3. After the merge, the push run redeploys the same content with the CI token. That run is the check of the token and secrets (briefing "Next"). Afterwards `wrangler logout` drops the laptop login.

## The CORS check (criterion 3)

The API already allows exactly `https://ourplayers.adveis.dev` (`CORS_ORIGINS` set in S10b). Checked before the deploy:

```
curl -sS -i -H 'Origin: https://ourplayers.adveis.dev' https://api.ourplayers.adveis.dev/v1/meta  → 200, access-control-allow-origin: https://ourplayers.adveis.dev
curl -sS -i -H 'Origin: https://evil.example' https://api.ourplayers.adveis.dev/v1/meta           → 200, no access-control-allow-origin (the browser blocks the read)
```

After the deploy Claude repeats both, and the live site loading Today proves it from a real browser. No server change.

## Console steps (owner)

1. **Cloudflare API token** (for CI): My Profile → API Tokens → Create Token → template **Edit Cloudflare Workers**. Account Resources: your account. Zone Resources: Specific zone → `adveis.dev` (the template's Workers Routes permission is what a custom domain needs). Continue → Create → copy the token once.
2. **Repo secrets**, in a terminal on your computer: `gh secret set CLOUDFLARE_API_TOKEN` (paste the token) and `gh secret set CLOUDFLARE_ACCOUNT_ID` (Account ID from the Cloudflare dashboard's account home, right column / "Copy account ID").
3. **`wrangler login`** for the first deploy (above).
4. **Phone tests** (criterion 1–2): desktop browser and Android Chrome open the site, Today loads; a deep link (`/player/nhl-8478402`) survives a reload; "Add to Home Screen" from Settings opens the help page; Android home-screen install opens standalone with the "OP" icon.
5. **iPhone check, later (owner, 2026-10-27):** no iPhone is available in this session. When the owner meets a friend with an iPhone: Safari → Add to Home Screen → opens standalone with the icon. If it works the owner says so; if not, a separate iPhone-fix session follows. The briefing's Next carries it, and criterion 1 stays open for iPhone until then.
