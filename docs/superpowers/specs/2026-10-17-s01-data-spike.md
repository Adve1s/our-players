## Polite client — `apps/server/src/http/polite-client.ts`

```ts
type PoliteClientOptions = {
  userAgent: string;
  fetch?: typeof globalThis.fetch;     // injected in tests
  minIntervalMs?: number;              // 1000, per host
  timeoutMs?: number;                  // 15000
  maxRetries?: number;                 // 3
  baseDelayMs?: number;                // 1000; delay = base * 2^attempt + jitter
  random?: () => number;               // jitter source, injected in tests
};
type PoliteResponse = { url: string; status: number; text: string; bytes: number };
export function createPoliteClient(o: PoliteClientOptions): {
  get(url: string): Promise<PoliteResponse>;  // 2xx → response; other 4xx / exhausted retries → throws HttpError(url, status)
  readonly requestCount: number;              // every attempt that hit the network, retries included
};
export function userAgent(version: string, contactUrl: string): string; // "OurPlayers/<version> (+<contactUrl>)"
```

- Spacing: per-host "next allowed" timestamp; requests to one host queue (no parallel bursts), different hosts don't wait on each other. Uses `setTimeout`/`Date.now`, so Vitest fake timers control it.
- Retries on 429, 5xx and network/timeout errors; `Retry-After` (seconds or HTTP date) replaces the computed backoff when present. A `Retry-After` over 60 s throws `HttpError` instead of sleeping (a job shouldn't block for an hour; the next scheduled run retries). No retry on other 4xx.
- Spacing is per hostname: `api-web.nhle.com` and `api.nhle.com` count separately.
- Timeout via `AbortController` + `setTimeout` (works under fake timers).
- Config: `loadConfig` gains `contactUrl` (env `CONTACT_URL`, default `https://github.com/Adve1s/our-players`); version from `apps/server/package.json` (add `"version": "0.1.0"`).
- **Tests** (`apps/server/test/polite-client.test.ts`): fake `fetch` (`vi.fn` returning `Response` objects) + `vi.useFakeTimers()`, assert on call times. One test per criterion-1 item: spacing per host (and none across hosts), 429 and 503 retried with growing delays, `Retry-After` honored, timeout aborts and retries, 404 not retried, User-Agent header sent. Red/green.

- Writes `apps/server/test/fixtures/<source>/<endpoint>/<name>.json` (body pretty-printed with 2-space indent so diffs are readable — my call; the upstream byte count stays in meta) and `<name>.meta.json` `{ url, fetchedAt, status, bytes }`. `<name>` = `--as` value or the id.
- Refuses to overwrite an existing file without `--force` (exit 1, names the file). Refuses non-2xx (nothing written).
- The write step (`recordFixture(client, clock, dir, …)`) is a pure-ish function with a small test (writes both files; refuses overwrite; `--as` name) using a fake client and a temp dir.

## Spike — `pnpm spike --date YYYY-MM-DD` (`apps/server/scripts/spike/`, throwaway, no tests)

- **NHL:** one `skater-bios` + one `goalie-bios` request filtered to Latvia (`cayenneExp=seasonId=<season> and nationalityCode="LVA"`, or `birthCountryCode` if `nationalityCode` doesn't exist) → set of Latvian player IDs. Then `score/{date}` → box score of each game → print Latvians' lines (G-A-P, +/-, shots, TOI; goalie SV/SA, decision). ~2 + 1 + games-with-Latvians requests, because the bios rows carry the team abbreviation.
- **NBA:** `scoreboard` → the `roster` of each team playing (≤ 30 requests; carries `birthPlace` — verified on one roster during recording before the spike is written) → Latvians → `summary` of their games → print MIN/PTS/REB/AST/FG/3PT/FT. If rosters lack birthplace, the per-athlete call is too expensive for every player; the spike then stops and I bring the alternative back to you instead of improvising.
- Ends with `requests: N (per host …), runtime: X s`.
- **Demo date is a recent October 2026 date** (NBA preseason / NHL opening weeks) where both leagues have a Latvian playing — picked from a recorded scoreboard. ESPN team rosters are current-season only, so a 2025-26 date could miss players who changed teams (Porziņģis' contract ended after 2025-26). The spike carries `shortcut: NBA Latvians come from current rosters, so old dates can miss traded players; S04a's recap reads stored players instead`.
- Reads JSON as `unknown` and narrows with small local type assertions — throwaway code, no zod yet (zod arrives with the adapters).
- Root script `"spike": "pnpm --filter @our-players/server spike"`; `apps/server/tsconfig.json` includes `scripts` so it typechecks.
